# Dev log: Sat 14 Nov 2026 (jam day 3)

Game: **Fix It In Post**. The agent changed today: Fable usage ran out, so the work continues on Claude Opus 5.5.

## The first bug a human found
Shane played the build and reported: "the guards face the opposite way and still catch the player". The agent had
played every scene many times through screenshots and logs and never noticed it, because at the game camera's distance
a figurine's face is a few pixels. The simulation was right: the watchman *was* looking at ACE. Only the models were
wrong: every Meshy figurine stood back to front (one yaw constant, `FigureYaw`, was +90 where it needed -90).

How it was found and checked: high-resolution screenshots (`HighResShot 2`) of four scenes, cropped around each figure,
compared with the facing the level file gives (the watchman starts facing south, ACE east). The badge on the
watchman's cap pointed north and ACE's face pointed west, so both were reversed. After the one-line fix, the same crops
show faces, walking direction and the glowing sight tiles agreeing.

![Before and after: the watchman's face now points along his sight line](img/15-guard-facing-fix.png)

## AI in the loop (Glass Box)
- What the human did: played the game and named the symptom in one sentence.
- What the agent did: traced it to the visual layer (the sight code and the model rotation share one direction table,
  so the logic could not disagree with itself), proved it with screenshots, fixed it, rebuilt, re-checked, packaged.
- Lesson: automated checks proved the rules work; only a person playing noticed the game *looked* unfair.
